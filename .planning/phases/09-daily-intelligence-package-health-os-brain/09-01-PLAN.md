# Phase 9 Plan 01: DIP Domain Contract & Daily Readiness Engine

## Metadata
- **Phase**: 9 — Daily Intelligence Package & Health OS Brain
- **Plan**: 09-01

## Objective
Establish the deterministic domain contracts for FitKarma's Daily Intelligence Package (DIP) and implement the `DailyReadinessCalculator` that synthesizes sleep, vitals, workout strain (ACWR), and hydration into an interpretable 0–100 score with statutory non-medical disclosures and missing-data handling.

## Scope of Work

### 1. DIP Domain Models (`lib/features/brain/domain/dip_models.dart`)
- `ReadinessTier`: Enum (`peak`, `optimal`, `moderate`, `recovery`).
- `ReadinessFactor`: Value object representing an individual scored dimension (`name`, `score` 0–100, `weight` 0.0–1.0, `summary`, `isMissing`).
- `DailyReadinessScore`: Value object containing:
  - `score` (integer 0–100)
  - `tier` (`ReadinessTier`)
  - `headline` (concise summary string)
  - `explanation` (detailed breakdown)
  - `factors` (`List<ReadinessFactor>`)
  - `statutoryDisclaimer` (explicit non-diagnostic wellness notice)
  - `calculatedAt` (`DateTime`)
- `DipActionCategory`: Enum (`hydration`, `nutrition`, `movement`, `recovery`, `mindset`).
- `DipMicroAction`: Value object for an actionable recommendation:
  - `id` (`String`)
  - `title` (`String`)
  - `description` (`String`)
  - `category` (`DipActionCategory`)
  - `priority` (`double` 0.0–100.0)
  - `actionRoute` (`String?` e.g., deep-link route)
  - `actionLabel` (`String`)
  - `isDismissible` (`bool`)
  - `culturalContext` (`String?` e.g., "*Shatapawali post-meal strolling tradition*")
- `DipFocusSignal`: Top-level daily focus item (`title`, `subtitle`, `badge`).
- `DailyIntelligencePackage`: Unified root container:
  - `date` (`DateTime`)
  - `readinessScore` (`DailyReadinessScore`)
  - `primaryFocus` (`DipFocusSignal`)
  - `topActions` (`List<DipMicroAction>` clamped to max 3)
  - `summaryMetrics` (steps, calories, sleep, water today)
- `DipContextInput`: Aggregated input payload passed to calculators and rule engines:
  - `userId` (`String`)
  - `timestamp` (`DateTime`)
  - `sleep` (`SleepRecord?`)
  - `todaySteps` (`int`)
  - `restingHeartRate` (`double?`)
  - `acuteWorkload` (`double` e.g., rolling 7-day tonnage)
  - `chronicWorkload` (`double` e.g., rolling 28-day weekly average tonnage)
  - `consumedCalories` (`double`)
  - `targetCalories` (`double`)
  - `consumedWaterMl` (`int`)
  - `targetWaterMl` (`int`)
  - `recentMealTimestamp` (`DateTime?`)
  - `recentMealCalories` (`double?`)

### 2. Daily Readiness Calculator (`lib/features/brain/domain/daily_readiness_calculator.dart`)
- Implement `calculateReadiness(DipContextInput input) -> DailyReadinessScore`:
  - Calculate **Sleep Factor** (35% weight): Duration vs 8-hr target + quality rating.
  - Calculate **Vitals Factor** (25% weight): Resting heart rate against nominal healthy baseline (55–75 bpm).
  - Calculate **Workload Strain Factor** (25% weight): ACWR evaluation (0.8–1.3 optimal = 100, >1.5 high strain = 40).
  - Calculate **Hydration/Nutrition Factor** (15% weight): Water intake pacing relative to hour of day.
  - Dynamic weight normalization: if any factor is missing (e.g. sleep unrecorded or no heart rate monitor), distribute remaining weights proportionately to compute an accurate score without throwing errors.
  - Grade into `ReadinessTier` and attach statutory wellness disclosure: *"Wellness indicator only. Not intended to diagnose, cure, or treat any medical condition."*

### 3. Unit Tests (`test/features/brain/daily_readiness_calculator_test.dart`)

- Test readiness tier classification across peak, optimal, moderate, and recovery thresholds.
