# Phase 11 Plan 01: Server-Side WhatsApp Webhook & Verification Engine

## Metadata
- **Phase**: 11 — WhatsApp AI Logging
- **Plan**: 11-01
- **Focus**: Webhook infrastructure, Meta signature verification, phone number resolution, and interaction logging
- **Status**: Ready to execute

## Objective
Implement the server-side entry point for the Meta WhatsApp Business Cloud API inside Supabase Edge Functions. Build the GET verification challenge handler, HMAC-SHA256 signature verifier, phone number normalizer, and `public.profiles` account linker. Create the `whatsapp_interactions` Postgres schema with RLS and deduplication guarantees.

## Scope of Work

### 1. Database Schema (`supabase/migrations/20261103000001_whatsapp_interactions.sql`)
- Create table `public.whatsapp_interactions`:
  - `id uuid primary key default gen_random_uuid()`
  - `user_id uuid references auth.users(id) on delete cascade` (nullable for unlinked sender attempts)
  - `wa_message_id text unique not null` (Meta `wamid` for deduplication)
  - `phone_number text not null`
  - `message_type text not null` (`text`, `audio`, `interactive`)
  - `raw_input text` (original text or voice transcript)
  - `candidate_items jsonb default '[]'::jsonb`
  - `total_calories numeric(6, 1) default 0.0`
  - `total_protein numeric(5, 1) default 0.0`
  - `total_carbs numeric(5, 1) default 0.0`
  - `total_fat numeric(5, 1) default 0.0`
  - `status text not null default 'pending'` (`pending`, `confirmed`, `cancelled`, `unlinked_user`, `expired`)
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`
- Enable RLS:
  - Users can select their own interactions (`auth.uid() = user_id`).
  - Service role has full read/write access.

### 2. Edge Function: `whatsapp-webhook/`
- Directory: `supabase/functions/whatsapp-webhook/`
- Files:
  - `index.ts`:
    - Handles `GET`: Meta challenge handshake (`hub.mode === 'subscribe'`, `hub.verify_token`, `hub.challenge`).
    - Handles `POST`: Inbound message routing, HMAC verification, phone lookup, and response dispatch.
  - `signature.ts`:
    - `verifyMetaSignature(rawBody: string, signatureHeader: string | null, secret: string): boolean`
    - Validates `sha256=<hex_digest>` using crypto `hmac` in constant-time.
  - `phone_matcher.ts`:
    - Normalizes WhatsApp `from` (e.g., `919876543210` -> `+919876543210`).
    - Looks up user profile in `public.profiles`.
    - Returns matched user or unlinked status.
  - `schemas.ts`:
    - TypeScript definitions for Meta webhook payload, text message, audio message, and interactive button reply.
  - `meta_client.ts`:
    - Sends outbound text / template messages to WhatsApp Cloud API (`POST /v21.0/{phone_number_id}/messages`).
    - Handles unlinked user notification template.

### 3. Automated Test Suite (`supabase/functions/whatsapp-webhook/test.ts`)
- Test 1: GET webhook challenge verification succeeds with valid token, rejects invalid token.

- Test 4: Inbound deduplication detects existing `wa_message_id` and skips duplicate processing.
- Test 5: Unlinked phone number triggers friendly invitation response.
