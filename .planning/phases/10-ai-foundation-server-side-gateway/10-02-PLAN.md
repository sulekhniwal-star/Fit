# Phase 10 Plan 02: Dart AI Gateway Client & Meal Analyzer Pipeline

## Metadata
- **Phase**: 10 — AI Foundation & Server-Side Gateway
- **Plan**: 10-02
- **Focus**: Flutter client AI gateway integration, Indian food database normalization, and Hinglish coaching (TASK 060, TASK 061)
- **Status**: Ready to execute

## Objective
Implement the client-side AI integration layer in Flutter. Build the `AiGatewayClient` communicating with Supabase Edge Functions, the `IndianFoodMatcher` that maps AI food tokens against the 500+ verified items in `DriftFoodCatalogRepository` with authentic yield and tadka calculations, and the Hinglish coaching formatter.

## Scope of Work

### 1. AI Domain Models (`lib/features/ai/domain/ai_models.dart`)
- `AiConfidenceLevel`: Enum (`high`, `medium`, `low`).
- `AiCandidateItem`:
  - `foodName` (`String`)
  - `quantity` (`double`)
  - `unit` (`PortionUnit`)
  - `cookingState` (`CookingState`)
  - `tadkaLevel` (`TadkaLevel`)
  - `estimatedCalories` (`double`)
  - `proteinGrams` (`double`)
  - `carbsGrams` (`double`)
  - `fatGrams` (`double`)
  - `confidence` (`double` 0.0–1.0)
  - `isVerifiedInCatalog` (`bool`)
  - `matchedCatalogFoodId` (`String?`)
- `AiHinglishInsight`:
  - `headline` (`String`)
  - `hinglishText` (`String` e.g., "*Dal tadka mein protein accha hai, but ghee thoda adjust kar sakte hain!*")
  - `tone` (`String`)
- `AiMealAnalysisResult`:
  - `summary` (`String`)
  - `candidateItems` (`List<AiCandidateItem>`)
  - `totalCalories` (`double`)
  - `totalProtein` (`double`)
  - `totalCarbs` (`double`)
  - `totalFat` (`double`)
  - `overallConfidence` (`AiConfidenceLevel`)
  - `uncertaintyReasons` (`List<String>`)
  - `coaching` (`AiHinglishInsight`)
  - `statutoryDisclaimer` (`String`)

### 2. Indian Food Matcher (`lib/features/ai/domain/indian_food_matcher.dart`)
- `IndianFoodMatcher`:
  - Injects `DriftFoodCatalogRepository` (Phase 6).
  - Queries local 500+ food database to find candidate item matches by name and Hinglish aliases (e.g. "Phulka", "Roti", "Chapati", "Dal Tadka", "Moong Dal").
  - If catalog match is found:
    - Normalizes nutrition against verified database densities.
    - Resolves authentic Indian portion units (`PortionUnit.smallKatori`, `mediumKatori`, `largeKatori`, `roti`, etc.).
    - Marks `isVerifiedInCatalog: true`.
  - If no match found:
    - Retains AI estimated values with `isVerifiedInCatalog: false` and adds an uncertainty reason.

### 3. AI Gateway Client (`lib/features/ai/data/ai_gateway_client.dart`)
- `AiGatewayClient`:
  - Communicates with Supabase Edge Function `/functions/v1/ai-gateway`.
  - Sends standard request envelope (`request_id`, `idempotency_key`, `payload`).
  - Supports `analyzeMealText(String prompt)` and `analyzeMealPhoto(Uint8List imageBytes)`.
  - Enforces 15-second timeout and typed `Result<T>` responses handling `FK-xxxx` errors.
- `MockAiGatewayClient`:
  - Fully deterministic mock returning realistic multi-dish Indian meal responses for testing.
- Riverpod Providers:
  - `aiGatewayClientProvider`: Returns `AiGatewayClient` or mock based on configuration.
  - `indianFoodMatcherProvider`: Injects food catalog repository.
  - `aiMealAnalyzerServiceProvider`: High-level service combining client request and food database normalization.

### 4. Unit & Normalization Tests
- `test/features/ai/ai_meal_analyzer_test.dart`:
  - Tests parsing text meal inputs (e.g. "2 rotis, 1 katori dal tadka, half katori paneer bhurji").
  - Tests malformed and ambiguous JSON responses (graceful fallback).
  - Tests Hinglish coaching separation from numeric macro calculations.
- `test/features/ai/indian_food_matcher_test.dart`:
  - Tests matching against seeded Drift food catalog items.
  - Tests fallback behavior when an unknown food dish is analyzed.
